# AOD 桌面网页端重设计规格

## 1. 概述

本轮将 AOD 前端从深色霓虹、长页面堆叠式界面，重构为适合本地多 Agent 编排工作的双层工作台。浅色区域承载导航、指标、群组、任务和交付操作；深色区域只承载实时讨论、日志、冲突和风险信息。

桌面界面采用左侧导航、中央工作区和右侧上下文检查器。检查器可拖动伸缩、收起并恢复上次宽度，中央区域按真实可用空间重排，不缩放字体或整体页面。

## 2. 本轮范围

### 2.1 目标

- 重设计运行中心、Agent 群组、任务检查器、冲突审查和 GitHub 交付的桌面界面。
- 保留现有任务、运行、群组、Reviewer、GitHub 和 SSE API 行为。
- 提升信息密度、状态可读性、操作确定性和长期运行时的可观测性。
- 拆分当前集中在 `app.js` 和 `styles.css` 中的前端职责，但不引入框架或构建工具。
- 在 1440px、1280px 和 1024px Chrome 视口完成验收。

### 2.2 非目标

- 本轮不实施、不验收 390px 移动端布局。
- 不修改 SQLite 模型、Agent 调度、Git 合并和 Reviewer 的业务语义。
- 不迁移到 React、Vue 或其他前端框架。
- 不增加新的生产依赖或构建步骤。

### 2.3 延期方案

移动端任务详情采用独立全屏页面，通过返回按钮回到任务列表，并恢复原列表的滚动、筛选和选择状态。该方案只记录，不进入本轮代码和测试。

## 3. 视觉系统

- 页面背景使用浅灰 `#edf1f1`，主要操作面为白色。
- 实时讨论、日志、冲突和风险使用深色工作面 `#182326`。
- 青绿色表达运行、在线和通过；珊瑚红用于主要命令；琥珀色用于等待和警告；红色仅用于失败和危险操作。
- 主容器圆角为 8px，按钮和输入框为 6px，状态与 Agent 角色为胶囊标签。
- 表格行、日志行和结构分隔线保持直线，不将所有内容卡片化。
- 页面标题控制在 20-24px；正文使用清晰的中文界面字体；commit、分支、ID 和日志使用等宽字体。
- 间距使用 4px/8px 基准。阴影仅用于对话框、抽屉、悬浮和拖动状态。
- 动效持续 140-240ms，使用克制的淡入、状态反馈和布局重排，并支持 `prefers-reduced-motion`。

## 4. 桌面工作台结构

### 4.1 左侧导航

- 导航包含运行中心、Agent 群组、任务、GitHub 交付和设置。
- 默认展开，可收起为仅图标窄栏；刷新后恢复偏好。
- 当前页面使用背景、图标和文字三重状态表达，不只依赖颜色。

### 4.2 顶栏

- 固定显示当前仓库、分支、运行模式、Agent 并发槽位和连接状态。
- `manual / hybrid / auto` 使用分段控件，旁边显示模式允许自动推进到哪一步。
- SSE 断线时顶栏出现明确重连状态，不覆盖最后一次成功数据。

### 4.3 中央工作区

- 运行中心按指标带、活动群组、任务表格和运行列表组织，不使用大型 Hero。
- 任务表格支持状态、Agent 和运行单元筛选。
- 点击任务只更新右侧检查器，不离开当前列表。
- 中央区域使用容器查询适配检查器宽度：指标自动换列，任务表隐藏次要列，运行列表在空间不足时折叠。

### 4.4 右侧检查器

- 默认宽度 360px，可拖动范围为 280-560px。
- 收起后保留 52px 操作轨道；重新打开恢复上次宽度。
- 拖动条支持鼠标、键盘方向键、`Shift + 方向键` 大步调整和双击恢复默认宽度。
- 主工作区随检查器宽度真实重排，不使用页面缩放或字体缩放。
- 检查器包含概览、实时输出、验收和审查标签页。
- 宽度和收起状态存入 `localStorage`。

## 5. Agent 群组运行中心

- 群组页复用同一工作台外壳，右侧检查器切换为会话与共识检查器，不增加第四列。
- 中央区域左侧显示成员、职责、并发占用和轮次状态，右侧为深色讨论时间线。
- 时间线按轮次分段，区分 Agent 输出、主持者总结、系统事件和操作者消息。
- 开始、暂停、继续和取消固定在页面顶栏；取消必须二次确认。
- 操作者消息明确标注“下一轮生效”。
- 会话检查器展示成员快照、讨论进度、风险、共识和 DAG。
- DAG 使用可编辑表格，字段错误就地显示，包括循环依赖、文件范围冲突、无效角色和不允许的验收命令。
- 确认 DAG 后创建运行并进入运行中心。
- 在 1024px 下成员区缩为窄栏，优先保留聊天和共识检查器。

## 6. 运行、任务与交付

- 任务检查器展示状态时间线、当前 commit、worktree、实时输出、验收结果、检查结论和修复次数。
- 操作按钮只在对应状态出现，例如启动 Agent、重新验收、进入合并门禁和确认合并。
- 禁止通过点击状态文字隐式修改业务状态。
- 合并冲突进入独立审查视图，展示双方 diff、Reviewer 建议和补丁确认。应用补丁与重试合并始终需要人工确认。
- GitHub 交付显示认证状态、远程仓库、PR、CI checks 和 required checks。发布 PR 与合并 PR 分开，GitHub 合并始终需要确认。
- 长日志支持搜索、级别筛选、虚拟滚动和自动跟随开关。用户主动向上滚动后停止自动跳到底部。
- SSE 推送任务、进程、验收、合并、审查、群组和 CI 事件；断线恢复按最后事件 ID 补齐。

## 7. 前端结构

本轮保持原生前端和零构建步骤，将职责拆为少量 ES 模块：

- `app.js`：入口、路由和初始化。
- `ui/api.js`：请求、错误规范化和 SSE 连接。
- `ui/state.js`：服务端状态、当前选择和订阅通知。
- `ui/layout.js`：导航、检查器、偏好和布局行为。
- `ui/run-center.js`：运行、任务、Reviewer 和 GitHub 交付视图。
- `ui/group-console.js`：群组、会话、消息、成员和共识视图。
- `ui/dialogs.js`：创建任务、运行、群组和会话对话框。

CSS 拆为：

- `styles/tokens.css`：颜色、字号、间距、圆角和动效变量。
- `styles/shell.css`：应用外壳、导航、顶栏、中央区域和检查器。
- `styles/components.css`：按钮、表格、状态、表单、对话框和日志。
- `styles/views.css`：运行中心、群组、冲突和交付页面规则。

`index.html` 只保留应用外壳、主要页面挂载点和对话框结构。入口改为 `type="module"`，不引入打包器。

## 8. 状态与路由

- 服务端数据以 `/api/state` 和详情 API 为唯一真实来源。
- SSE 事件触发对应视图的定向更新；不得将临时 DOM 状态当作任务完成状态。
- 使用 hash 路由保存当前页面和选择，例如运行、任务、群组会话和交付视图。
- 刷新和浏览器前进/后退恢复当前上下文。
- `localStorage` 只保存布局偏好、日志自动跟随和表格列偏好，不保存运行、任务或认证数据。
- 使用统一 `data-action` 事件委托，避免重新渲染后监听器失效。

## 9. 异常与可访问性

- API 失败在对应区域显示错误和重试，不清空最后一次成功数据。
- SSE 断线显示固定状态条并自动重连。
- 空任务、无群组、无日志和未连接 GitHub 均显示明确空状态和唯一下一步操作。
- 提交期间按钮进入忙碌状态并阻止重复操作。
- 危险操作使用确认对话框。
- 图标按钮提供可访问名称与 tooltip；焦点样式可见；状态不只依赖颜色。
- 日志和时间线使用克制的 `aria-live` 更新，避免逐行打断屏幕阅读器。
- 动画不改变周边布局边界，减少动态效果时关闭非必要动画。

## 10. 验收与测试

### 10.1 自动测试

- 保留现有后端、群组和前端测试。
- 增加 hash 路由恢复、检查器宽度与收起状态、SSE 更新、操作门禁、表单校验和偏好恢复测试。
- `npm run check` 必须通过。
- `npm test` 必须通过。

### 10.2 Chrome 验收

只使用用户的 Google Chrome，在 1440px、1280px 和 1024px 视口验证：

- 无横向溢出、文字重叠或控件遮挡。
- 左侧导航展开与收起正常。
- 检查器拖动、键盘调整、收起、恢复和主区重排正常。
- 任务表列降级、指标换列和运行列表折叠正常。
- 群组消息、共识编辑、运行状态、日志、冲突和 GitHub 视图与 API 一致。
- SSE 断线与恢复状态可见。
- 减少动态效果时没有非必要动画。

## 11. 完成条件

- 桌面工作台视觉与已确认的 Chrome 原型一致。
- 现有业务功能和 API 保持兼容。
- 自动测试全部通过。
- Chrome 三个桌面视口验收通过。
- 移动端代码未纳入本轮改动。
